# ChatKit Web 产品设计初稿

> 基于 [ChatKit Middleware API 文档](../chatkit-middleware/docs/API_REFERENCE.md) 的 Web 前端产品设计初稿，供评审与迭代。

---

## 1. 产品定位与目标

**产品名称**：ChatKit Web（暂定）

**定位**：面向 ChatKit Middleware 后端的一站式 Web 客户端，让用户通过浏览器完成登录、对话、文档笔记管理与记忆/画像查看。

**目标用户**：  
- 主要：需要与 AI 对话、管理个人内容、查看长期记忆的终端用户。  
- 次要：内部体验与联调、演示与验收。

**核心价值**：  
- 统一入口：认证、会话、AI 问答、文档、笔记、画像与记忆均经同一 Web 应用访问。  
- 与后端契约一致：所有能力以 [API_REFERENCE.md](../chatkit-middleware/docs/API_REFERENCE.md) 及 API Gateway（默认 `http://localhost:26100`）为唯一对接标准。

---

## 2. 功能模块与 API 映射

功能模块按 API 文档五大章划分，便于与接口一一对应。

| 模块 | 对应 API 文档章节 | 核心能力 | 主要接口（经 api-gw） |
|------|-------------------|----------|------------------------|
| **认证与账号** | 一、认证与账号 | 注册、登录、刷新令牌 | `POST /auth/register`、`POST /auth/login`、`POST /auth/refresh` |
| **会话与消息** | 二、会话与消息 | 历史会话列表、会话内容、Inbox、SSE 实时消息 | `GET /conversation/sessions`、`GET /conversation/messages`、Inbox 列表、SSE 订阅 |
| **AI 问答** | 三、AI 问答 | 与 AI 对话（含流式回复） | `POST /llm/chat/completions`（推荐，支持 stream） |
| **用户内容** | 四、用户内容 | 文档与笔记的 CRUD（笔记为自由文本 memo，非 Todo 待办） | 文档：`/api/documents/*`；笔记：`/api/notes/*` |
| **记忆与画像** | 五、记忆与画像 | 用户画像查看/编辑、长期记忆列表/搜索/详情/删除、时序图 | Profile：`/api/profile/{user_id}`；Memory：`/api/memory/*`、`/api/temporal/*` |

**技术约束**：  
- 所有请求经 **API Gateway**（Base URL 可配置，默认 `http://localhost:26100`）。  
- 除登录/注册/刷新外，需在请求头携带 **JWT**（如 `Authorization: Bearer <access_token>`）；网关校验后注入 `X-User-ID`。  
- **X-Request-ID** 必填，建议使用 `crypto.randomUUID()`，便于链路追踪。

## 3. 信息架构与页面结构（初稿）

整体采用**个人助理**式界面：登录后主界面为**单页三栏**布局，减少导航切换，充分利用 Web 横向空间。会话、笔记、文档在同一屏内分区展示；**个人中心**（画像 + 记忆整合为一页）、系统消息通过右上角入口进入。

```
ChatKit Web
├── 未登录
│   ├── 登录页（/login）
│   └── 注册页（/register）
│
└── 已登录
    ├── 主工作台（/）— 三栏布局，见下方「3.1 主工作台（个人助理）设计」
    │   ├── 左侧栏：历史会话列表 + 新会话
    │   ├── 中间区：聊天（当前会话消息 + 发消息 / 流式回复 + 翻看历史）
    │   └── 右侧栏：上块「投资笔记」、下块「工作档案」
    │
    ├── 顶栏右上
    │   ├── 消息通知图标 → Inbox 历史消息（/inbox）；有新消息时显示红点
    │   └── 我的图标 → 个人中心（/me），单页内整合画像 + 记忆
    │
    ├── 消息 / Inbox（/inbox）— 由顶栏「消息通知」进入
    │   └── Inbox 消息列表（分页）、已读/未读、可选 SSE 实时拉取
    │
    └── 个人中心（/me）— 由顶栏「我的」进入，单页内两区
        ├── 用户画像区：查看/编辑（GET/PUT /api/profile/{user_id}）
        └── 长期记忆区：列表、语义搜索、详情/删除、时序图（/api/memory/*、/api/temporal/*）
```

**MVP 范围**：接口文档中已有的能力在本版中**全部实现**，即认证、会话与消息、AI 问答、文档、笔记、画像、记忆（含时序）均纳入 MVP，不做裁剪。

### 3.0 登录页与注册页

未登录用户访问需鉴权页面时跳转至**登录页**（`/login`）；无账号用户可从登录页进入**注册页**（`/register`）。两页均为居中表单布局，与 API 文档「一、认证与账号」对应。

#### 3.0.1 登录页（/login）

**布局**：单栏居中卡片，含 Logo/标题、表单、跳转注册链接。

```
+------------------------------------------+
|              Logo / ChatKit Web          |
|                                          |
|    [ 账号：邮箱 / 用户名 / 手机号 …… ]   |
|    [ 密码：……………………………………… ]   |
|                                          |
|              [ 登录 ]                    |
|                                          |
|    还没有账号？ [ 去注册 ]                |
+------------------------------------------+
```

| 项 | 说明 |
|----|------|
| **路由** | `/login`。已带有效 JWT 访问时可直接跳转主工作台（/）。 |
| **表单** | **账号**：邮箱、用户名或手机号（至少填其一，与后端一致）。**密码**：必填。提交时调用 `POST /auth/login`，Body：`email` 或 `username` 或 `phone_number`、`password`。 |
| **成功** | 200 返回 `user_id`、`access_token`、`refresh_token`、`expires_in`。前端保存令牌（内存 + 可选持久化），跳转主工作台（/）。 |
| **失败** | 401 时展示后端返回的 `message`（如「账号或密码错误」「请先验证您的邮箱」等），不跳转。 |
| **跳转注册** | 页内提供「去注册」链接，跳转 `/register`。 |

**交互与降级**：请求头带 `X-Request-ID`；网络/5xx 时友好提示并可重试。

#### 3.0.2 注册页（/register）

**布局**：单栏居中卡片，含 Logo/标题、表单、跳转登录链接。

```
+------------------------------------------+
|              Logo / ChatKit Web          |
|                                          |
|    [ 邮箱（选填）…………………………… ]   |
|    [ 手机号（选填）………………………… ]   |
|    [ 密码（≥8 位，必填）…………… ]   |
|    [ 姓名（选填）…………………………… ]   |
|    [ 用户名（选填，3–50 位）………… ]   |
|    [ 验证码（选填，6 位）……………… ]   |
|                                          |
|              [ 注册 ]                    |
|                                          |
|    已有账号？ [ 去登录 ]                  |
+------------------------------------------+
```

| 项 | 说明 |
|----|------|
| **路由** | `/register`。已登录用户访问时可跳转主工作台（/）。 |
| **表单** | **邮箱**、**手机号**至少填其一。**密码**必填，≥8 位。可选：`name`、`username`（3–50 位，仅字母数字下划线）、`code`（6 位验证码，与后端契约一致）。提交时调用 `POST /auth/register`。 |
| **成功** | 201 返回 `user_id`、`email`、`email_verified`、`message`。可提示「注册成功，请登录」并跳转登录页（/login），或自动带出邮箱/手机号便于用户直接登录。 |
| **失败** | 400 时展示后端 `message`（如「该邮箱已被注册」「密码长度至少 8 位」等），不跳转。 |
| **跳转登录** | 页内提供「去登录」链接，跳转 `/login`。 |

**交互与降级**：请求头带 `X-Request-ID`；邮箱/手机号格式、密码长度等可做前端校验，最终以后端 400/201 为准。

### 3.1 主工作台（个人助理）设计

登录后主界面（`/`）为**个人助理**式单页：垂直方向分为**三块**——左（会话）、中（聊天）、右（笔记 + 档案），无需在多个全屏页面间切换。

**布局**（桌面端）：

```
+----------------------------------------------------------------------------------------------------------+
| 顶栏：Logo | 个人助理 / ChatKit                    [ 消息通知 🔴 ]  [ 我的 ▼ ]                            |
+----------------------------------------------------------------------------------------------------------+
| 左侧栏（会话）     |  中间区（聊天）                                    |  右侧栏（垂直两段）           |
| 固定宽度，可折叠   |  主内容区，自适应宽度                               |  固定宽度，可折叠             |
+-------------------|------------------------------------------------------|-----------------------------+
| [+ 新会话]        |  当前会话：{会话标题或「新对话」}                     |  ┌─ 投资笔记 ─────────────┐  |
|                   |                                                      |  │ 查询（列表/单条）   │  |
| 会话 1            |  消息列表（按时间正序，可上滑加载更早历史）           |  │ 添加 / 修改 / 删除     │  |
| 会话 2  ← 当前    |  ─────────────────────────────────────────────────  │  │ GET/POST/PATCH/DELETE /api/notes     │  |
| 会话 3            |  输入框：[输入消息………………………………] [发送]              │  └─────────────────────────┘  |
| ...               |  回复以流式展示（SSE）                              |  ┌─ 工作档案 ─────────────┐  |
| （来自            |                                                      |  │ 文档列表（最近/全部）   │  |
|  /conversation/   |                                                      |  │ 上传/预览/编辑/删除     │  |
|  sessions）       |                                                      |  │ [对应文档服务 API]     │  |
|                   |                                                      |  └─────────────────────────┘  |
+-------------------|------------------------------------------------------|-----------------------------+
```

**三栏说明**：

| 区域 | 内容与数据来源 | 交互 |
|------|----------------|------|
| **左侧：历史会话 + 新会话** | 「+ 新会话」按钮；会话列表来自 `GET /conversation/sessions`（分页，按 last_message_at 倒序）。后台不返回会话名称，每项标题由**该会话最后一条消息**内容截断展示（选中会话后由 `GET /conversation/messages` 第一页取到），副标题可展示 last_message_at 或消息条数。 | 点击某会话 → 中间区加载该会话消息（`GET /conversation/messages`），并基于该会话进行 AI 对话。点击「新会话」→ 中间区清空，为新对话。 |
| **中间：聊天** | 当前选中会话的消息列表（`GET /conversation/messages`，分页上滑加载更早历史）；用户输入 + 发送 → `POST /llm/chat/completions`（建议 `stream: true`），流式展示 AI 回复。 | 在此与 AI 对话、翻看该会话历史；切换左侧会话即切换中间内容。 |
| **右侧上：投资笔记** | 笔记服务 API（自由文本 memo，非 Todo 待办）：**查询**（列表/单条）、**添加**、**修改**、**删除**，见下方「投资笔记（控制台）功能」。 | 在右侧栏内完成笔记的查询、新建、编辑、删除，不离开主工作台。 |
| **右侧下：工作档案** | 文档列表（文档服务 API），支持最近/全部；上传、预览、编辑、删除。**支持格式**：PDF、Word（.doc/.docx）、Excel（.xls/.xlsx）、PPT（.ppt/.pptx）、图片（.jpg/.png/.gif/.webp/.svg）、文本（.txt/.csv/.md）。**单文件大小**：默认上限 50MB（可配置）。 | 在右侧栏内完成文档的浏览与操作，不离开主工作台。 |

**顶栏右上**：

| 入口 | 行为 | 数据与反馈 |
|------|------|------------|
| **消息通知图标** | 点击后进入 Inbox 页（/inbox）或打开消息抽屉，查看历史系统消息。 | Inbox 列表（分页、已读/未读）；若有新消息，图标上显示**红点**；可选 SSE 订阅实时新消息。 |
| **我的** | 点击后进入**个人中心**单页（/me）；或为下拉菜单，含「个人中心」「**退出登录**」。该页内**上为用户画像**（内容不多，紧凑一块）、**下为长期记忆**（列表、搜索、详情/删除、时序图），不用 Tab，一屏上下分区。 | 画像：GET/PUT /api/profile/{user_id}。记忆：GET /api/memory、POST /api/memory/search、GET/DELETE /api/memory/by-id/{id}、/api/temporal/*。退出登录：清除本地令牌并跳转 /login。 |

**投资笔记（控制台右侧）功能**

主工作台右侧「投资笔记」区块提供完整笔记 CRUD，与笔记服务契约一致（`contracts/support/notes-store.yaml`，见 API 文档 §7）。

| 功能 | 说明 | 接口（经 api-gw） |
|------|------|-------------------|
| **查询笔记** | 列表：分页、排序（最近/全部）；单条：按 id 查看详情。 | 列表：`GET /api/notes?page_size=…&page_token=…&sort=desc`；单条：`GET /api/notes/{id}`。 |
| **添加笔记** | 新建一条笔记，内容为自由文本（memo）。 | `POST /api/notes`，Body：`{ "content": "…" }`。 |
| **修改笔记** | 编辑已有笔记内容。 | `PATCH /api/notes/{id}`，Body：`{ "content": "…" }`。 |
| **删除笔记** | 删除一条笔记，需可二次确认。 | `DELETE /api/notes/{id}`。 |

笔记对象字段：`id`、`userId`、`content`、`createdAt`、`updatedAt`。列表返回 `items`、`next_page_token`。错误与鉴权按 API 文档（401/404/500 等）处理。

**交互与降级**：

- **侧栏折叠**：左、右栏采用**抽屉式**交互。折叠时侧栏滑出视口（或收成窄条/图标），中间聊天区扩大；点击侧边按钮或图标可再次滑入展开。默认可保持右侧展开，用户可主动收起以专注聊天。
- 右侧「投资笔记」「工作档案」若内容过多，可在各自区块内滚动或分页；与笔记/文档服务的接口保持一致。
- 未读消息数若接口未直接返回，红点可基于「上次查看时间」与消息时间戳推断，或先做「有/无」红点，后续随 API 补充精确数字。
- 移动端：三栏可改为 Tab 或抽屉切换（左-中-右依次），或默认只显示中间聊天，左/右通过顶部或侧边按钮呼出。

**与路由的关系**：主工作台对应根路径 `/`；Inbox 为独立页（/inbox），个人中心为单页（/me，内含画像 + 记忆），由顶栏入口进入，用完可返回主工作台。

### 3.2 个人中心（用户中心）页面设计

从顶栏「我的」进入**个人中心**页（路由 `/me`），单页内**上为用户画像、下为长期记忆**，一屏内上下分区展示，**不用 Tab**：画像内容不多，紧凑放在上方即可，下方直接是记忆列表与操作。

**布局**（桌面端）：

```
+----------------------------------------------------------------------------------------------------------+
| 顶栏：Logo | 个人中心                    [ 返回工作台 ]              [ 消息通知 ]  [ 我的 ▼ ]  [ 退出登录 ]   |
+----------------------------------------------------------------------------------------------------------+
|                                                                                                          |
|  【用户画像】 内容不多，紧凑一块                                                                           |
|  ┌────────────────────────────────────────────────────────────────────────────────────────────────────┐  |
|  | 风险偏好：moderate    投资期限：medium    资产偏好：[...]    资产排除：[...]    人生事件：[...]      |  |
|  | 更新时间：2025-01-15  version：2                                                    [ 编辑 ] [ 保存 ] |  |
|  └────────────────────────────────────────────────────────────────────────────────────────────────────┘  |
|                                                                                                          |
|  【长期记忆】  时间轴倒序 + 按类型区分样式                                                                  |
|  ┌────────────────────────────────────────────────────────────────────────────────────────────────────┐  |
|  | [ 语义搜索：输入关键词………………… ] [ 搜索 ]    类型筛选：[ 全部 ▼ ]   [ 时序图 ]                       |  |
|  | ─────────────────────────────────────────────────────────────────────────────────────────────────  |  |
|  | 时间轴（竖线 + 节点，按 created_at 倒序，最新在上）                                                     |  |
|  |   ● 2025-01-15 14:30   [情景]  content 摘要…                    [ 详情 ] [ 删除 ]   ← episodic       |  |
|  |   │                                                                                                  |  |
|  |   ● 2025-01-15 12:00   [语义]  content 摘要…                    [ 详情 ] [ 删除 ]   ← semantic      |  |
|  |   │                                                                                                  |  |
|  |   ● 2025-01-14 18:00   [程序]  content 摘要…                    [ 详情 ] [ 删除 ]   ← procedural    |  |
|  |   │                                                                                                  |  |
|  |   ● 2025-01-14 12:00   [情绪]  content 摘要…                    [ 详情 ] [ 删除 ]   ← emotional      |  |
|  |   · 加载更多                                                                                          |  |
|  | ─────────────────────────────────────────────────────────────────────────────────────────────────  |  |
|  | 详情 → GET /api/memory/by-id/{id}；删除前二次确认；时序图 → /api/temporal/search、snapshot。         |  |
|  └────────────────────────────────────────────────────────────────────────────────────────────────────┘  |
|                                                                                                          |
+----------------------------------------------------------------------------------------------------------+
```

**区块说明**：

| 区域 | 内容与数据来源 | 交互 |
|------|----------------|------|
| **顶栏** | 与主工作台一致（Logo、消息通知、我的）；「个人中心」标题与「返回工作台」按钮，点击返回 `/`。右侧提供**退出登录**入口（可与「我的」并列，或放在「我的」下拉中）。 | 返回工作台、消息入口、我的下拉、**退出登录**。 |
| **用户画像区**（上方一块） | `GET /api/profile/{user_id}`：`user_id`、`version`、`updated_at`；可选：`risk_tolerance`、`investment_horizon`、`asset_preferences`、`asset_exclusions`、`life_events`、`attributes`。内容不多，单块展示即可。 | 只读展示 +「编辑」进入表单/内联编辑，「保存」调用 `PUT /api/profile/{user_id}`。404 时「暂无画像，点击编辑完善」或新建（PUT 写入）。 |
| **长期记忆区**（下方主区） | 搜索：`POST /api/memory/search`；列表：`GET /api/memory`（limit/offset、memory_type），**按时间轴倒序**（`created_at` 新→旧）。**四种类型**（以 memory-store 契约为准）：**episodic（情景）**、**semantic（语义）**、**procedural（程序性）**、**emotional（情绪）**。 | 搜索 + 类型筛选 → 列表刷新；**时间轴**竖线+节点展示，**样式按类型区分**（颜色/图标/标签）；列表项「详情」「删除」（删除二次确认）；「时序图」展示图/时间线。 |

**记忆列表：时间轴 + 类型样式**

- **时间轴倒序**：列表以**时间轴**形式展示，按 `created_at` **倒序**（最新在上）；左侧竖线 + 节点，节点对应一条记忆，右侧为内容摘要与操作。
- **四种类型、样式区分**：**以 API 契约为准**（`contracts/shared/memory-store.yaml`），`memory_type` 枚举为 **episodic（情景）**、**semantic（语义）**、**procedural（程序性）**、**emotional（情绪）**，共 4 种。前端在样式上**按此 4 种区分**，便于一眼识别：
  - **情景（episodic）**：如一种颜色/左边框/图标（如事件图标）。
  - **语义（semantic）**：如另一种颜色/左边框/图标（如知识图标；含偏好、目标等抽象信息）。
  - **程序性（procedural）**：如再一种颜色/左边框/图标（如步骤/习惯图标）。
  - **情绪（emotional）**：如第四种颜色/左边框/图标（如情绪/感受图标）。
  - 实现时可用**标签（Tag）**+**节点/线条颜色**或**卡片左边框色块**区分，具体色值与图标由视觉规范约定。

**说明**：全系统已统一为上述 4 种 memory_type（存储、API、时序图/HSG 一致）。偏好、目标在分类时归入 semantic。详见 [MEMORY_TYPE_ALIGNMENT.md](./MEMORY_TYPE_ALIGNMENT.md)（若有）。

**时序图（temporal）**：对应接口 `POST /api/temporal/search`、`POST /api/temporal/snapshot`，用于时序知识图谱的语义搜索与某时间点快照。**暂缓**，后续迭代再设计入口与展示。

**退出登录**：

- 个人中心页顶栏提供**退出登录**入口（按钮或「我的」下拉项）。点击后：清除本地 `access_token`、`refresh_token`（及任意持久化登录态），并跳转至登录页（`/login`）。后端无单独登出接口时，仅前端清令牌即可。

**交互与降级**：

- 画像区无数据（404）时展示「暂无画像，点击编辑完善」或「新建画像」，提交时 PUT 写入。
- 记忆区列表为空时展示「暂无记忆」；搜索无结果时展示「未找到相关记忆」。
- 删除记忆等敏感操作需二次确认；请求失败时保留当前视图并提示错误。
- 移动端：同一上下布局，画像块在上、记忆区在下，时序图可全屏或抽屉展示；退出登录入口保持可见（顶栏或菜单内）。

## 4. 关键流程简述

### 4.1 认证流程

1. 用户打开 Web，未带有效 JWT → 跳转登录页（或注册页）。  
2. **注册**：填写邮箱/手机号、密码等 → `POST /auth/register` → 成功后引导登录。  
3. **登录**：填写账号 + 密码 → `POST /auth/login` → 获得 `access_token`、`refresh_token`、`expires_in`。  
4. 前端保存令牌（如内存 + 可选持久化），后续请求在 Header 中带 `Authorization: Bearer <access_token>`。  
5. 当 access_token 过期时：用 `POST /auth/refresh` + `refresh_token` 换新令牌，再重试原请求。

### 4.2 对话流程

1. **会话列表**：登录后进入主工作台（`/`）→ 左侧栏请求 `GET /conversation/sessions?user_id=...&limit=20&offset=0`（user_id 可从 JWT 解析或登录态获取）。  
2. **选会话 / 新建**：在左侧选择某 session 或点击「+ 新会话」。  
3. **拉消息**：中间区根据当前 session_id 请求 `GET /conversation/messages?session_id=...&limit=20&offset=0`，分页上滑拉取更早消息。  
4. **发消息 / 收回复**：  
   - 用户在中间区输入内容后，将当前会话上下文（含历史消息）组装为 `messages`，调用 `POST /llm/chat/completions`。  
   - 建议使用 `stream: true`，以 SSE 方式流式展示 AI 回复。  
   - 前端需把用户消息与助手回复写入本地状态；若后端有「会话落库」能力，可按契约在适当时机同步。

### 4.3 个人中心（画像 + 记忆）

- 顶栏点击「我的」进入个人中心页（/me）。  
- **画像区**：用当前 user_id 调用 `GET /api/profile/{user_id}` 展示，编辑后 `PUT /api/profile/{user_id}`。  
- **记忆区**：用 `GET /api/memory/{user_id}` 列表、`POST /api/memory/search` 搜索、`GET /api/memory/by-id/{id}` 看详情、`DELETE` 删除；时序能力用 `/api/temporal/search` 与 `/api/temporal/snapshot` 展示图或时间线。  
- 页内不用 Tab：上为用户画像（紧凑一块），下为长期记忆，一屏上下分区，无需切换。

## 5. 非功能需求（初稿）

- **兼容性**：支持现代浏览器（Chrome、Firefox、Safari、Edge 等近期版本）。  
- **响应式**：优先保证桌面端体验，移动端可后续迭代。  
- **错误与鉴权**：  
  - 401 时清除本地令牌并跳转登录。  
  - 403 时提示无权限，不暴露后端细节。  
  - 网络/5xx 统一友好提示，并可选重试。  
- **请求规范**：所有请求带 `X-Request-ID`；敏感操作（如删除记忆）可增加二次确认。
